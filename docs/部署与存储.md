# 部署与存储

所有照片都通过自己的相册服务访问。手机和网页后台都不保存云厂商的长期访问密钥。云存储的流量和存储费用由自己的云账号承担。

当前 App 为 2.12.0，服务端与管理员网页后台接口为 2.9.2。使用多宝宝、六位邀请码和简洁权限设置时，请配合使用这组版本。一个服务同时提供 App 接口与 `/admin/` 网页，无需额外安装前端服务。

一套部署供一个家庭使用，可以管理多位宝宝；这不是为陌生家庭提供独立租户的托管平台。各宝宝分别管理资料、家人权限、成长记录和故事册，共用家庭账号、存储配置、备份及上传大小限制。家庭相册名称也是全局设置，宝宝名字单独编辑。使用方法见 [多宝宝相册](多宝宝相册.md)。

## 首次登录

全新部署使用 `admin` 作为用户名和初始密码。连接服务地址后，在 App 登录页或网页后台填写 `admin/admin`，按提示设置自己的新密码，完成后才能进入相册。新密码为 8～200 个字符，不需要使用随机长字符串。请先完成首次改密，再向家人分享相册地址。

默认账号只在建立全新相册时生成一次。已有相册升级、重启或更换程序都不会恢复成 `admin/admin`；即使已有管理员被停用，也不会重新生成一个默认管理员。请保留原数据目录，使用当前账号登录。

进入后可以在 App 的“我的 → 账号与安全”或后台“设置 → 账号与安全”修改用户名或密码。修改用户名需要当前密码，不影响照片、收藏和留言归属；保存后，其他设备需用新账号重新登录。

如果希望由服务器主人凭专属口令创建管理员，可在第一次启动前设置 `ALBUM_BOOTSTRAP_TOKEN`，填写至少八个字符的自选设置口令。Docker 部署可在 `.env` 中增加这一项；启动后在 App 选择首次设置，或按后台登录页提示填写口令。使用这种方式的新相册不会创建 `admin/admin`。旧版尚未完成首次设置的相册也继续使用原来的设置口令；需要查看时运行：

```sh
docker compose exec album cat /data/setup-code.txt
```

设置完成后口令文件会移除。默认登录方式无需运行上面的命令。

## 网页后台与 Docker

本机启动后打开 `http://127.0.0.1:8765/admin/`；远程部署后，打开相册服务地址下的 `/admin/`。网页使用与 App 相同的家庭管理员账号。宝宝管理员只管理被授权宝宝，和其他普通家人一样不能进入管理后台。浏览器通过 Cookie 保持登录，写入操作还会检查来自当前页面的请求。后台功能见 [网页管理后台](网页管理后台.md)。

`compose.yaml` 把相册数据保存在持久化数据卷中，原始图库通过 `./library:/library:ro` 挂载。后台页面已包含在服务端镜像内，执行 `docker compose up -d --build` 即可更新。请沿用原数据卷；不要为了更新网页删除已有数据。

反向代理应把 `/admin/` 和 `/api/` 一起交给同一个相册服务，并正确传递用户访问的域名和 HTTPS 信息。只代理接口会导致后台打不开；将网页与接口拆到不同域名也不适用于当前的登录方式。

HTTPS 反向代理需要保留原来的 `Host`，并传递 `X-Forwarded-Proto`。Compose 使用 `.env` 中的 `ALBUM_TRUSTED_PROXIES` 指定可信反向代理的实际来源地址，默认 `127.0.0.1`；仅在本机直接测试时无需修改。正确识别 HTTPS 后，后台才能按实际访问方式设置登录 Cookie 并检查同源请求。

Docker 场景中，宿主机反向代理连接容器时，来源常是 Docker 网桥地址。应填写实际来源地址，不要照抄其他部署的固定地址，也不要设置为通配符 `*`。例如 Nginx 的代理位置需要包含：

```nginx
proxy_set_header Host $http_host;
proxy_set_header X-Forwarded-Proto $scheme;
```

这两行需放在自己已配置的反向代理规则中；可信来源还需在 `.env` 中单独设置，修改后重建相册服务。

## 先分清服务地址和存放位置

连接相册时填写的服务地址，是**运行相册后端的网址**。手机通过这个地址登录、浏览和上传。

照片存放位置，是**后端保存照片和视频文件的地方**。选择“自己的服务器”时，这里填写运行后端那台机器上的硬盘文件夹；相册后端、数据库和照片可以放在同一台 Linux 服务器上。先在电脑上测试时，后端运行在电脑上，文件夹也位于这台电脑。

选择 NAS 或对象存储后，手机仍连接同一个相册后端，由后端读写所选位置。NAS 共享地址、云存储地址不作为手机登录相册的服务地址。

## 选择存储

| 方案 | 适合的情况 | 需要准备 |
| --- | --- | --- |
| 自己的服务器 | 后端、数据库和照片放在同一台服务器；也适合先用电脑测试 | 运行后端那台机器上允许相册读写的硬盘文件夹 |
| NAS | 已经有家庭 NAS，或希望集中备份 | 先在运行后端的机器上挂载共享目录，再允许相册使用 |
| 阿里 OSS | 已经使用阿里云 | 私有存储桶、所在地域、访问密钥 |
| 腾讯 COS | 已经使用腾讯云 | 带账号后缀的完整存储桶名称、地域、访问密钥 |
| 通用 S3 | 兼容 S3 的云服务或自建对象存储 | 服务地址、存储桶、地域、密钥、寻址方式 |

存储配置由家庭管理员管理，对所有宝宝共同生效。合照可被多位宝宝收录，原文件只保存一份；切换当前宝宝不会切换新上传的存放位置。

已有服务器硬盘空间时，可以先选“自己的服务器”，完成账号和备份配置后再按需接入 NAS 或云存储。App 2.12.0 的“我的 → 照片存放”只列已经配置的位置，点右上角“添加”选择方式。填写后点“连接并保存”；成功后进入详情，需要切换时再选“用于新上传”。网页后台仍从“存储与备份 → 存放位置”添加、测试并选择上传位置。

自己的服务器优先使用允许的默认文件夹，也能展开手动目录；NAS 需要先在服务器挂载。OSS、COS 直接填写区域、存储桶与密钥；S3 还需填写服务地址。照片子目录、临时凭证等放在更多连接设置中。区域或存储桶名称应按云控制台中的真实配置填写。

连接检查前会先保存配置。检查失败时保留表单，再次提交继续使用刚保存的位置；如果网络中断导致保存结果无法确认，先返回列表查看，避免重复添加。已有照片的位置不能直接更换目录或存储桶，但仍可改名称和更新密钥。

连接测试会在专用测试位置写入一份很小的临时文件，读取后删除；不会移动相册。需要有读取、写入和删除该位置的权限。请为相册准备单独的存储桶或独立目录前缀，并使用只允许访问相应位置的账号。

## 自己的服务器与 NAS

“自己的服务器”填写的是**运行后端那台机器上的目录**，供后端直接保存和读取文件。把后端、数据库与照片一起部署在 Linux 服务器时，就使用这一项。手机上的路径不能填写在这里。默认只允许使用相册数据目录内的上传文件夹。增加其他目录，需要由服务器主人设置 `ALBUM_STORAGE_ROOTS`。

Linux 示例：

```sh
export ALBUM_STORAGE_ROOTS='["/mnt/family-album"]'
```

Windows 示例：

```powershell
$env:ALBUM_STORAGE_ROOTS='["D:/FamilyAlbum"]'
python tools/start_local.py
```

NAS 的共享登录和挂载由运行后端那台机器的操作系统管理，相册不保存 NAS 密码。先在这台机器上完成挂载，再确认服务进程能读取和写入挂载目录。使用 Docker 时，自选硬盘文件夹和 NAS 挂载目录都需要让容器能够访问，在 `compose.yaml` 的 `volumes` 中增加映射，例如：

```yaml
      - /mnt/family-album:/mnt/family-album
```

同时在 `.env` 设置 `ALBUM_STORAGE_ROOTS=["/mnt/family-album"]`，重建容器后，在应用里填写 `/mnt/family-album`。容器使用普通用户运行，目录需要允许用户编号 10001 访问。

## 允许从哪些服务器目录导入

“导入与任务”可以读取服务器上已经存好的照片，复制到相册当前的新上传位置。开始任务前选择目标宝宝，任务会记住创建时的选择，之后切换网页所选宝宝不改变任务目标。完全相同的原文件可以加入其他宝宝相册，不重复保存。默认允许读取 `ALBUM_LIBRARY` 指定的图库；Docker 中对应 `/library`，即项目的 `library` 文件夹。

需要增加其他来源目录时，在 `.env` 设置绝对路径列表：

```dotenv
ALBUM_IMPORT_ROOTS=["/mnt/import-photos"]
```

使用 Docker 时，还要在 `compose.yaml` 的 `volumes` 中增加只读挂载：

```yaml
      - /mnt/import-photos:/mnt/import-photos:ro
```

重建服务后，后台会列出允许的目录。选择目录，再填写其中的子文件夹即可；网页不接受任意绝对路径、上级目录、隐藏目录或符号链接。每批扫描最多检查一万个文件，数量较多时请按子文件夹拆分。

`ALBUM_IMPORT_ROOTS` 决定从哪里读取旧文件，`ALBUM_STORAGE_ROOTS` 决定允许把新文件存到哪些本地位置，两者用途不同。导入会保留来源文件，后续仍应自行管理和备份来源目录。

## 上传限制和备份空间

`ALBUM_MAX_UPLOAD_BYTES` 是部署时设定的单个文件上限，默认 2 GB。家庭管理员可在后台“设置”中降低实际上传上限，不能超过部署上限。限制对全家庭统一生效，同时用于 App、网页上传和目录导入。

电脑上传会先写入服务端数据目录中的暂存区，再导入所选存储，因此即使原件最终存到云端，服务器仍需有足够的临时空间。

完整备份覆盖全家庭的所有宝宝、家人权限、成长记录和故事册，并包含全部已记录的原件；不会只备份当前选择的宝宝。后台备份目前只写入服务端数据目录下的 `backups` 文件夹，Docker 中为 `/data/backups`。恢复副本写入同一数据目录下的 `restored` 文件夹。完整备份和恢复都需要额外磁盘空间；设置照片存储为 OSS、COS 或 S3，不会改变备份的保存位置。完成后可下载备份到另一台设备，操作和恢复限制见 [备份与升级](备份与升级.md)。

## OSS 与 COS

阿里 OSS 使用地域服务地址，例如 `https://oss-cn-hangzhou.aliyuncs.com`，选择完整存储桶名称和对应地域。OSS 使用存储桶域名寻址，不能按普通路径方式拼接存储桶。

腾讯 COS 使用地域服务地址，例如 `https://cos.ap-guangzhou.myqcloud.com`，存储桶名称需要包含控制台给出的账号后缀。请复制控制台中的完整名称。

界面分别提供这两种服务的入口，服务端按对应地址规则连接。修改配置时，密钥框留空表示继续使用原密钥。已有密钥不会回显到手机；需要更换时直接填写新密钥。

## 通用 S3 与内网地址

通用 S3 可填写自建服务或其他兼容服务的地址。根据服务文档选择“存储桶域名”或“地址路径”寻址。兼容 S3 不代表所有供应商的所有功能完全一致，接入后应先做小批上传、下载和视频播放检查。

默认仅允许正常的公网 HTTPS 地址。自建服务位于局域网或本机时，需要服务器主人明确允许完整地址，例如：

```sh
export ALBUM_STORAGE_ALLOWED_ENDPOINTS='http://127.0.0.1:18333,https://storage.home.example:9000'
```

Docker 中的 `127.0.0.1` 指相册容器自身。另一个容器应使用同一网络的服务名称，并在允许列表填写对应完整地址。这里填的是服务器访问对象存储的地址，与手机访问相册的地址不同。

## 更换存储与旧照片

选择新的默认存储，只改变之后上传内容的目的地。每份照片和视频都记录自己的存放位置，因此换设置后，旧文件仍可读取。

这一版不提供自动搬迁历史照片。不要直接修改一个正在使用的配置，让它指向另一处空目录或存储桶。需要搬家时，应先完整备份、复制文件并验证，再安排迁移；原位置在确认之前继续保留。原导入图库也应保持原目录可用。

## 升级到多宝宝版本

保留原数据目录、图库、存储密钥和配置后，更新服务端与 App。首次启动 2.8.0 时，原有照片、留言、家人、成长记录和故事册一次性归到原来的宝宝，已有账号和登录会话继续有效。新增宝宝不会自动把普通家人加入，需要单独邀请或设置访问范围。

旧 App 没有宝宝选择能力，只能使用默认可访问的宝宝；请让家人一并安装新版，使用原签名覆盖更新。不要通过新建空数据卷或重建账号来升级。操作顺序见 [备份与升级](备份与升级.md)。

## 对外访问

默认部署只监听本机，便于先测试。局域网使用可将 `.env` 中的 `ALBUM_BIND_ADDRESS` 改为 `0.0.0.0`。外网使用请在相册前配置 HTTPS 反向代理，只公开需要的访问入口，云存储桶保持私有。

本机测试可以使用 HTTP。正式使用建议使用 HTTPS，避免账号密码和家庭照片在网络传输中被旁人读取。应用通过相册服务读取对象存储文件，因此服务器需要具备相应带宽，视频拖动进度依赖存储的分段读取能力。
